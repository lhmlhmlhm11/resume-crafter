# Resume Crafter — 简历工坊

面向应届毕业生与职场人的简历全流程工具：**口述经历 → 精美简历 → 岗位定制 → 投递体检 → 面试准备**。

## 何时使用

用户提到以下任一意图时启用：
- 做一份简历 / 简历模板 / 改简历 / 美化简历 / 排版简历
- 根据岗位 JD 调整简历、让简历符合招聘要求、针对某公司定制
- 投多个岗位需要多版简历
- 写求职信、准备面试
- 给简历加一寸照片

## 核心原则（必须遵守）

1. **绝不编造经历。** 缺失的信息一律留空并向用户询问，绝不用"看起来合理"的内容填充。
2. **先问再写。** 用户口述通常零散且缺时间、缺数字。动笔前先补齐关键字段。
3. **文字是资产。** 所有内容用真实可选中的文本，不做图片化文字、不用图标字体、不用表格排版正文。
4. **一次问完。** 用一次 AskUserQuestion 批量确认所有缺失项，不要挤牙膏式追问。
5. **改写要留痕。** 润色文案时，明确告知用户哪些表述被改了、为什么改，让用户能否决。

## 工作流程

### 第 1 步：采集信息

把用户口述的内容拆解为结构化字段。**优先从用户原话中提取**，缺什么再问。

必须齐备的字段：
- 姓名、联系方式（手机 + 邮箱，至少各一个）
- 求职意向（目标岗位或身份标签，如"电商运营实习生"）
- 教育经历：学校、专业、学历、起止时间
- 经历（实习/工作/项目）：单位、职位、时间、具体做了什么
- 技能、证书、获奖（有则填）
- 证件照（可选，见下方"照片位"）

用 AskUserQuestion 一次性确认缺失项。问题要具体，例如：
> "这段实习有没有具体的数据？比如转化率提升了多少、GMV 做了多少、团队多少人 —— 面试官必问，没有数字的经历会显得很空。"

### 第 2 步：改写文案

对每条经历描述做三件事：

**① 改成 STAR 式的成果句** — 结构：动词 + 做法 + 量化结果

| 原始 | 改写后 |
|---|---|
| 负责公众号运营 | 重排选题节奏并做读者访谈，单篇平均阅读量从 800 提升至 2600 |
| 参与了双十一活动 | 策划大促活动，累计带来 GMV 约 42 万元，超额完成月度目标 23% |
| 学会了 Excel 数据透视表 | 用数据透视表搭建店铺周报看板，输出选品/流量/转化三段漏斗分析 |

**② 换掉空洞动词** — 「负责、协助、参与、熟悉、精通、了解」→ 「搭建、主导、设计、优化、策划、分析」。原则：**用具体动作代替身份描述**。

**③ 规范措辞与标点** — 中文用全角标点；数字统一半角；中英文之间留空格；不用「…等」「等等」；单条 bullet 控制在 60 字内。

**④ 检查信息缺口** — 缺时间、缺成果、缺角色的条目，列出来让用户补。要**明确说明为什么需要**（如"没有数字的描述在面试中撑不住"），而不仅是机械提示。

完整改写指南与动词库见 `references/writing-guide.md`。

### 第 3 步：选择外观

外观由**四个正交维度**组合而成，任意组合都成立：

| 维度 | 取值 | 决定什么 |
|---|---|---|
| **版式** `--style` | 9 套（见下表） | 版面结构：页眉形态、分区标题样式、是否分栏 |
| **底板** `--surface` | `white` 纯白 / `ivory` 米白 / `mist` 雾灰 / `sage` 苔绿 / `ink` 深墨 | 纸面颜色与整套文字色 |
| **配色** `--palette` | `indigo` 靛蓝 / `teal` 青碧 / `clay` 赭红 / `plum` 紫罗兰 / `amber` 琥珀 / `graphite` 石墨 / `crimson` 绛红 | 主色及其派生色阶 |
| **密度** `--density` | `airy` / `normal` / `compact` / `dense` / `tight` | 行距、间距、页边距的松紧（默认按内容体量自动选档） |

**版式（9 套）**：

| 风格 | 适用 | ATS | 照片位置 | 默认配色 |
|---|---|---|---|---|
| `classic` | 默认首选。金融、法务、互联网通用，投递大厂/外企 | ✅ | 页眉右侧 | 靛蓝 |
| `modern` | 互联网、产品、运营、数据岗，现代感 | ✅ | 页眉右侧 | 青碧 |
| `elite` | 需要展示个人形象的通用岗，视觉层次强 | ✅ | 页眉右侧 | 靛蓝 |
| `neon` | 科技感、互联网产品岗。顶部渐变色带 + 反白姓名 | ✅ | 色带内 | 紫罗兰 |
| `geo` | 分区卡片式，留白充足。运营、活动岗 | ✅ | 页眉右侧 | 琥珀 |
| `academic` | 教师、科研、读博申请、外企学术 CV | ✅ | 页眉右侧 | 石墨 |
| `sidebar` | 设计师、产品经理，市场/品牌 | ⚠️ | 侧栏顶部 | 石墨 |
| `soft` | 轻盈不厚重。内容、文创岗 | ⚠️ | 侧栏顶部 | 青碧 |
| `creative` | 设计、品牌、内容创作 | ⚠️ | 顶部色带内 | 赭红 |

用 `python scripts/render_resume.py --list-styles` 查看全部，
用 `--list-themes` 查看全部底板与配色。

**规则**：
- 用户明确指定 → 照做。
- 用户提供了 JD → 用 `build_all.py --style auto` 或 `tailor_batch.py` 自动判断。
- 用户没指定也没给 JD → 默认 `classic` + `white` 底板 + `indigo` 配色，并在交付时说明还有哪些可选。
- **选了 `sidebar`/`soft`/`creative` 时，必须额外产出一份 `classic` 单栏版**作为线上投递兜底，
  并告知原因（部分 ATS 会跨栏错读）。
- **`ink` 深墨底板**仅在用户明确要深色时用：打印耗墨、线上投递需另备浅色版。
- **配色与 `meta.accent` 的关系**：只要显式指定了底板或配色（命令行或 JSON `meta.palette`），
  JSON 里遗留的 `meta.accent` 就不再生效 —— 这样一条数据能直接复用多套外观。

### 第 3.5 步：照片位（用户要求放照片时）

简历 JSON 中通过 `basic.photo` 指定照片：

| 字段 | 取值 | 说明 |
|---|---|---|
| `photo` | 本地路径 / URL / base64 | 相对路径以**简历 JSON 所在目录**为基准 |
| `photo_size` | `1in`(25×35mm) / `small1in` / `2in` / `square` / `boss`(200×250px) | 标准证件照规格 |
| `photo_shape` | `rect`(默认) / `rounded` / `circle` | 矩形最通用 |

要点：
- **未设 `photo` 时自动渲染带虚线的标准尺寸占位框**，提示用户该放什么尺寸，不留空白。
- 照片以 base64 内嵌进 HTML，PDF 渲染与单文件分享都不丢图。
- 提醒用户用**白底/蓝底正装证件照**，不要用生活照、自拍。
- 提醒：多数岗位不放照片更稳妥；国企、事业单位、公务员、前台/行政岗常要求附照片。

### 第 4 步：构建文件

```bash
# 一键构建（推荐）：质检 → HTML → PDF → DOCX → ATS 体检
python scripts/build_all.py resume.json --out ./输出目录 --style classic --name 张三

# 指定底板 / 配色 / 密度
python scripts/build_all.py resume.json --out ./输出目录 --style elite \
        --surface ivory --palette teal --name 张三

# 或分步执行
python scripts/render_resume.py resume.json --style classic --out ./out/张三.html
python scripts/html_to_pdf.py ./out/张三.html ./out/张三.pdf
python scripts/json_to_docx.py resume.json --out ./out/张三.docx
```

**Python 解释器**：直接用 `python` 即可。首次运行若缺 `python-docx` / `pypdf`，`scripts/_env.py` 会自动安装。

**PDF 依赖**：调用本机 Edge/Chrome/Brave 无头模式渲染，不需要额外下载。渲染产物是文本型 PDF（可复制可解析），不是图片型。

#### 一页适配（应届生必用）

应届生简历必须是一页。若内容较多，**不要删内容**，改用适配器自动收紧排版密度：

```bash
python scripts/fit_one_page.py resume.json --style elite --out-dir ./out --name 张三
```

它按「标准 → 紧凑 → 高密 → 偏紧 → 极限 → 微调」逐档收紧行距、分区间距、页边距与正文字号
（字号下限 10pt，不损可读性），每档实测 PDF 页数，命中单页即停。**内容一个字都不删**。

若用完所有档位仍超页，说明内容量确实超出一页容量 —— 此时向用户说明，让他决定删哪部分，
或产出两页版本（部分大厂接受两页，但应届生仍优先一页）。

**经验**：单页容量约等于「8 个分区块 + 16 条 bullet + 3 组技能」。
超出时优先合并同类项目条目（如挑战杯与国创赛合并为一条，奖项用 `note` 字段标注），而不是删 bullet。

#### 密度自动分档（默认行为）

渲染时若未显式指定 `--density`，会按内容体量自动选档（`theme.pick_density`）：

| 档位 | 何时选中 | 实测填充率 |
|---|---|---|
| `airy` | 内容较少（估算行数 ≤ 38） | 约 84%，底部留白舒适 |
| `normal` | 中等 | 约 80% |
| `compact` | 偏多 | 约 72% |
| `dense` | 很多 | 约 68% |
| `tight` | 极多（应届生超页时的最后手段） | 约 65% |

容量表由实测定标（渲染到 A4 后测正文底边位置 + PDF 页数），不是拍脑袋的估算。
**版面观感的两个关键点**（改 CSS 时务必保持）：

1. **密度档只改「系数」（`--*-scale`），风格只改「基值」（`--*-base`）。**
   若风格 CSS 直接写死 `--lh` / `--gap-section` 等最终值，会与同优先级的 `body.dens-*` 互相覆盖，
   密度分档将形同虚设（这是历史上真实踩过的坑）。
2. **派生变量必须声明在 `body` 上，不能写在 `:root`。**
   CSS 自定义属性的 `var()` 在声明它的元素上求值 —— 写在 `:root` 时 body 上的覆盖读不到。

### 第 5 步：JD 定制（用户提供了招聘要求时）

```bash
python scripts/jd_match.py resume.json jd.txt --out ./out/匹配报告.json
```

产出：关键词覆盖率、已命中项、缺失项、**按优先级排序的修改建议**。

**关键动作**：
- 把「必改」项（出现在 JD 任职要求/岗位职责区块的缺失技能）逐条拿给用户确认。
- 确认用户真实具备 → 帮他改写进简历（技能区显式列出 + 在相关经历里用案例佐证）。
- 用户不具备 → **明确告知这项缺失**，让用户决定是否投递。绝不代填。
- 加分项缺失只需提示，不构成阻碍。

**投多岗位时用批量定制**：
```bash
python scripts/tailor_batch.py resume.json --jd jd1.txt jd2.txt jd3.txt --out ./多岗位
```
一份底稿 → 每个 JD 一套 HTML/PDF/DOCX + 各自的匹配报告，且会自动按行业匹配风格。

### 第 6 步：求职信与面试准备（可选）

```bash
python scripts/cover_letter.py resume.json jd.txt --out ./求职信.md --interview \
  --company 字节跳动 --role "用户运营实习生"
```
产出求职信正文 + 基于 JD 的面试问题清单 + 回答框架 + 投递前自查表。

- `--company` 指定公司名后，正文用具体公司名替代「贵公司」，比通用称呼更显诚意。
- `--role` 显式指定岗位名；不指定时从 JD 推断（会跳过「职位要求」等结构性标签行）。

### 第 7 步：质检与交付

```bash
python scripts/lint_resume.py resume.json --style classic   # 内容体检
python scripts/ats_check.py ./out/张三.pdf                  # ATS 体检
```

**必须向用户交代**：
1. 产出了哪些文件（HTML/PDF/DOCX/报告），分别怎么用 —— PDF 用于投递，DOCX 用于后续修改，HTML 用于预览和改版。
2. 质检发现的**未修复问题**（尤其是信息缺口）。
3. 如果用了双栏风格，说明为什么额外给了单栏版。
4. 如果有 JD，报告覆盖率，并说明哪些缺失项是硬伤。
5. 文件命名建议：`姓名-岗位-年限.pdf`，不要用"简历.pdf""最终版2.pdf"。

最后用 present_files 展示 PDF 与 HTML（HTML 可直接预览）。

## 数据格式

简历 JSON 是唯一事实来源，字段定义见 `references/data-schema.md`。最小示例：

```json
{
  "meta": { "style": "classic", "surface": "white", "palette": "indigo" },
  "basic": {
    "name": "张三",
    "title": "电子商务专业 · 2027 届本科",
    "photo": "my-photo.jpg",
    "photo_size": "1in",
    "contact": [{ "type": "phone", "text": "138-0000-0000" }]
  },
  "summary": "一段 60—120 字的定位概述",
  "sections": [
    {
      "id": "experience", "title": "实习经历", "type": "experience",
      "items": [{
        "org": "某公司", "role": "电商运营实习生",
        "start": "2025.07", "end": "2025.09",
        "bullets": ["动词+做法+量化结果"]
      }]
    },
    { "id": "skills", "title": "专业技能", "type": "skills",
      "groups": [{ "label": "数据与工具", "items": ["Excel", "SQL"] }] }
  ]
}
```

`meta` 可选字段：

| 字段 | 取值 | 说明 |
|---|---|---|
| `style` | 9 套版式键名 | 默认 `classic` |
| `surface` | 5 种底板键名 | 默认 `white` |
| `palette` | 7 种配色键名 | 默认取风格的默认配色 |
| `density` | `airy`/`normal`/`compact`/`dense`/`tight` | 省略则按内容体量自动选档 |
| `accent` | `#RRGGBB` | 手工指定主色。**仅在未指定 surface/palette 时生效** |

## 排版规范速查

完整规范见 `references/design-system.md`，核心数字：

- 页面 A4，页边距 14mm（上下）× 16mm（左右），密度档可按比例缩放
- 姓名 21—26pt（随风格），正文 10.5pt（紧凑档最低 10pt），分区标题 11.5—12.5pt，元信息 9—9.5pt
- 行距 1.5（黄金区间 1.2—1.5），分区间距 4.6mm，条目间距 3.2mm
- **单一强调色**（靛蓝 #1F3A5F 首选），正文近黑 #1A1A1A，元信息灰 #6E6E6E
- **底板与配色正交**：5 种底板 × 7 种配色 = 35 种组合，派生色阶由 `theme.py` 自动计算
- **深色底板必须整套反色**：文字、分割线、面板、胶囊、照片占位框全部翻转
- **主色分「色块用」与「文字用」两套**：`--accent`（色块/描边，≥3:1）与 `--accent-text`（文字，≥4.5:1）。
  深墨底板上靛蓝只有 1.6:1，直接当标题色等于看不见 —— 引擎会自动提亮，不需要手动干预
- **深色底板的派生色有「可见下限」**：黑纸上 sRGB 混合既更弱又会吃掉色相（蓝灰变灰），
  引擎按「结构色 vs 底色」分档设对比度下限，不足就继续加大主色占比。
  结构线（`--accent-line`）≥1.6:1，装饰色（`--accent-soft`）≥1.35:1，底带 ≥1.15:1
- 遵守 F 型阅读路径：核心信息置于页面左上与上半部分
- 每段经历 3—6 条 bullet，每条不超过 2 行
- 单栏优于双栏；分区名用 ATS 标准词（教育经历/实习经历/项目经历/专业技能）
- **分区顺序分两种情形**：
  - 有实习/项目经历 → 个人简介 → 实习 → 项目 → 教育 → 技能 → 荣誉奖项（实践优先）
  - 无实习的在校生 → 个人简介 → 教育 → 实习/项目 → 技能 → 荣誉奖项（学历优先）
- 一页为主（应届生必守）；两页上限
- **单页容量参考**：约「8 个分区块 + 16 条 bullet + 3 组技能」。超出时先用 `fit_one_page.py` 收紧排版，
  仍超页则合并同类条目（如两项竞赛合为一条、奖项用 `note` 标注），而不是删 bullet
- **分区分页规则**：`.sec` 允许跨页（`avoid-page` 会造成整段被推到下一页、上一页大片留白），
  但分区标题与条目标题必须 `break-after: avoid`，否则会出现孤儿标题
- **技能区排版**：分组标签独占一行，胶囊在其下方整行铺开。
  不要改成「左标签 + 右胶囊」两栏网格 —— 胶囊列被标签挤窄，条目一多就产生孤儿行
- **照片占位框**：无照片时用轻量虚线描边 + 小字提示，不做填充底、不用大图标。
  占位框是「指引」不是「内容」，画得太重会在页眉留出扎眼的 25×35mm 空洞

## 常见陷阱（务必避开）

| 陷阱 | 正确做法 |
|---|---|
| 模板做成海报 | 信息优先，设计服务于可读性 |
| 双栏 + 图标 + 色块堆砌 | 线上投递用单栏 |
| 图片化姓名/联系方式 | 一律真实文本 |
| 表格排版正文 | 用 flex/grid 而非 table |
| 字号缩到 9pt 以下 | 不低于 10.5pt，宁可删内容 |
| 技能进度条（Excel ★★★★☆） | 换成具体能力描述 |
| 随手放生活照 | 白底/蓝底正装证件照 |
