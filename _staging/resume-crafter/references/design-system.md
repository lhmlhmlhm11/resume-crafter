# 排版设计系统

本文档定义 resume-crafter 的排版规范。所有数值来自主流简历设计指南与 ATS 兼容规范的交集。

---

## 一、页面与尺寸

| 项目 | 规范 | 理由 |
|---|---|---|
| 页面尺寸 | A4（210 × 297 mm） | 国内招聘标准 |
| 页边距 | 上下 14mm，左右 16mm | 不低于 1.5cm，避免打印裁切 |
| 内容宽度 | 178mm | 舒适的单栏行宽 |
| 打印 | 关闭浏览器页眉页脚 | 页眉页脚会被 ATS 跳过 |
| 分页保护 | 分区与条目 `break-inside: avoid` | 避免标题与内容被劈到两页 |
| 长度 | 应届生 1 页；经验 5 年内 1 页；10 年以上或项目密集 2 页 | 超过 10 年经验或需要展示大型项目时用 2 页 |

**关于两页**：即使做两页，第一页也必须能独立成立（包含基本信息、经历摘要、核心技能）；第二页不要重复页眉页脚的姓名联系方式（ATS 可能误判为重复文档）；两页之间用分隔线标注。

## 二、字体与字号

### 中文字体
首选 `Source Han Sans SC`（思源黑体），回退 `Microsoft YaHei`（微软雅黑）、`PingFang SC`（苹方）。保证在 Windows / macOS 上都能正确渲染。

### 字号体系

| 层级 | 字号 | 字重 | 说明 |
|---|---|---|---|
| 姓名 | 21—25pt | 700 | 视觉第一落点 |
| 身份标签 | 10.5pt | 500—600 | 求职意向 / 专业 + 年级 |
| 分区标题 | 12—12.5pt | 700 | 字间距 0.08em |
| 条目标题 | 10.8—11pt | 700 | 职位名加粗，组织名常规 |
| 正文 / bullet | 10.5pt | 400 | 全篇统一，不混用 |
| 元信息 | 9.5pt | 400 | 日期、地点、说明文字 |

**下限 10pt**。低于 10pt，部分 ATS 会当作噪声丢弃，HR 也要眯眼。

### 行距
正文 1.5，元信息 1.35，分区之间靠 margin 而非空行拉开。

## 三、颜色

### 三层解耦架构

外观的颜色不是写死在风格里的，而是三个正交维度：

```
底板（surface）  →  纸面颜色 + 整套文字色
   ×
配色（palette）  →  主色
   ↓
派生色阶（自动计算）→ 浅底、描边、胶囊、面板、分区标题底
```

**为什么要解耦**：早期版本把主色与底色硬编码在 6 套风格 CSS 里，
结果是「换配色要改 6 个文件」，且深色底板无从谈起 —— 因为浅底色是按白纸算的。

### 底板（5 种）

底板决定「纸是什么色、文字什么色」。深色底板会**整套反色**：
文字、分割线、面板、胶囊、照片占位框全部翻转，否则读不了。

| 键名 | 名称 | 纸面 | 适用 |
|---|---|---|---|
| `white` | 纯白 | `#FFFFFF` | 默认。ATS 与打印最稳，通用首选 |
| `ivory` | 米白 | `#FBF8F2` | 暖调纸面，适合打印与文艺/内容岗 |
| `mist` | 雾灰 | `#F4F6F9` | 冷调浅灰蓝，衬托深蓝主色，科技感 |
| `sage` | 苔绿 | `#F1F5EF` | 低饱和绿灰，环保/教育/公益行业观感好 |
| `ink` | 深墨 | `#12141A` | 深色底板。打印耗墨、部分 ATS 截图预览失真，线上投递需另备浅色版 |

### 配色（7 种）

配色只决定主色，其余色阶自动派生。

| 键名 | 名称 | 主色 | 适用 |
|---|---|---|---|
| `indigo` | 靛蓝 | `#1F3A5F` | 沉稳专业，金融/国企/外企通用 |
| `teal` | 青碧 | `#0F6E8C` | 清透现代，互联网/产品/运营岗主流 |
| `clay` | 赭红 | `#B04A2F` | 温暖有质感，内容/品牌/文化岗 |
| `plum` | 紫罗兰 | `#5B3E8E` | 创意出彩，设计/创意/互联网产品岗 |
| `amber` | 琥珀 | `#A86A12` | 明快亲和，运营/活动/销售岗 |
| `graphite` | 石墨 | `#33373D` | 近乎无彩，极简克制，学术与高端咨询风 |
| `crimson` | 绛红 | `#A32236` | 醒目有冲击力，赛事/创业/市场岗 |

### 派生色阶

全部由 `theme.py` 在 Python 端算好后注入 CSS 变量。
**不使用 `color-mix()`** —— 那需要 Chromium 111+，GitHub 用户环境不可控。

派生算法是「主色按比例混入纸面色」：

```
mix(主色, 纸面, 比例)  →  比例=0 全是纸面，比例=1 全是主色
```

| 变量 | 浅底比例 | 用途 |
|---|---|---|
| `--accent-soft` | 0.10 | 浅色块、斜切色块尾段、摘要竖线 |
| `--accent-line` | 0.34 | 描边、分隔线 |
| `--sec-h-bg` | 0.07 | 分区标题带底色 |
| `--chip-bg` | 0.06 | 技能胶囊底 |
| `--chip-border` | 0.17 | 技能胶囊描边 |
| `--card-bg` | 0.045 | 圆角卡片底（geo 风格） |

因为公式是「混入纸面」，深色底板下浅底自动变深底，规则天然成立。

#### 深色底板的派生色需要「可见下限」

深色纸面上 sRGB 混合有两个问题，浅色底板完全没有：

1. **感知更弱** —— 白纸上 10% 主色的 tint 明显可见，黑纸上 10% 几乎看不出层次
2. **色相被吃掉** —— 主色混向近黑的纸面后会褪成灰色，「蓝灰色块」变成「灰块」

所以深色底板不是简单「把比例乘 2」，而是给每种派生色设**对比度下限**，
低于下限就继续加大主色占比，直到在纸面上真的看得见：

| 变量 | 深底起始比例 | 对比度下限 | 为什么是这个下限 |
|---|---|---|---|
| `--accent-soft` | 0.18 | 1.35:1 | 斜切色块尾段与摘要竖线是装饰元素，低于此值等于隐形 |
| `--accent-line` | 0.40 | 1.60:1 | 结构线（描边 / 分隔线），必须清楚 |
| `--chip-border` | 0.30 | 1.40:1 | 胶囊描边是结构边 |
| `--sec-h-bg` | 0.14 | 1.15:1 | 标题底带可以含蓄，但不能消失 |
| `--chip-bg` | 0.12 | 1.12:1 | 胶囊底色 |
| `--card-bg` | 0.16 | 1.16:1 | 几何块底 |

**下限按「结构色 vs 底色」分档，不是一刀切。**
把含蓄底色和结构线用同一个标准要求，会逼着底色变得过重、抢走文字的注意力。

浅色底板完全不受影响 —— 原始比例与已确认的观感一致。

### 主色对比度保障

主色是为「色块 / 描边」设计的，**不一定能直接当文字色**。
靛蓝 `#1F3A5F` 在深墨底板 `#12141A` 上对比度只有 1.6:1 ——
直接拿来当分区标题色，等于看不见。

因此主题引擎产出两套主色：

| 变量 | 用途 | 对比度要求 |
|---|---|---|
| `--accent` | 色块、描边、分隔条 | ≥ 3:1（对纸面） |
| `--accent-text` | 分区标题、技能组标签、正文强调 | ≥ 4.5:1（对纸面） |

处理流程（`theme.py`）：

1. **深色底板先提亮主色**（`lift_for_dark`）：混入底板自己的 ink 色而非纯白，保住色相，
   直到对纸面对比度 ≥ 3:1。浅色底板完全跳过这一步 —— 原主色对比度本来就够，
   改动会破坏已确认的观感。
2. **再算文字色**（`readable_on`）：向白（深底）或向黑（浅底）调整到 ≥ 4.5:1。
3. **色块上的反白文字**（`--on-accent`）：按对比度自动选黑或白。

对比度用 WCAG 2.1 相对亮度公式计算（`contrast_ratio`）。
`doctor.py` 与 `selftest.py` 都会遍历 5 × 7 = 35 种组合做断言，防止回归。

### 排版节奏的两层结构

排版参数同样拆成两层，与颜色架构同源：

```
风格 CSS   →  基值（--lh-base / --gap-section-base / --gap-entry-base / --pad-y-base / --fs-body-base）
密度档      →  系数（--lh-scale / --gap-section-scale / ...）
最终值      →  calc(基值 × 系数)，声明在 body 上
```

**两条铁律**（改 CSS 时务必遵守）：

1. **风格不得写死最终值。** 若风格直接写 `--lh: 1.42`，会与同优先级的 `body.dens-compact`
   互相覆盖 —— 后注入的赢 —— 密度自动分档就形同虚设。
2. **派生变量必须声明在 `body` 上，不能写在 `:root`。**
   CSS 自定义属性的 `var()` 在声明它的元素上求值：写在 `:root` 时，
   body 上的 `--lh-base` 覆盖根本读不到。

`doctor.py` 会检查这两条，违反即报错。

### 密度档（5 档）

| 档位 | 行距 | 分区间距 | 条目间距 | 页边距 | 字号系数 |
|---|---|---|---|---|---|
| `airy` | ×1.05 | ×1.20 | ×1.15 | ×1.08 | ×1.00 |
| `normal` | ×1.00 | ×1.00 | ×1.00 | ×1.00 | ×1.00 |
| `compact` | ×0.93 | ×0.68 | ×0.72 | ×0.86 | ×0.972 |
| `dense` | ×0.87 | ×0.54 | ×0.58 | ×0.76 | ×0.952 |
| `tight` | ×0.80 | ×0.30 | ×0.30 | ×0.62 | ×0.952 |

字号下限 10pt（ATS 与可读性红线）—— 紧凑档只压行距与间距，不压字号。

**各档容量由实测定标**（渲染到 A4 后测正文底边位置 + PDF 页数），
不是拍脑袋的估算。`theme.DENSITY_CAPACITY` 记录了各档能舒适容纳的估算行数。

**反模式**：大面积色块、彩色背景、渐变（`neon` 风格除外）、超过两种颜色。招聘方要的是信息，不是设计稿。

## 四、布局结构

### 单栏（默认，ATS 首选）
```
姓名（居中或左对齐）
身份标签
联系方式（横排，· 分隔）
──────────────
个人简介（60—120 字）
──────────────
分区标题 ▌ 教育经历
  条目标题 ................... 日期
  组织名 / 说明
  · bullet
  · bullet
```

分区标题用**左侧 1.6mm 竖色条 + 标题 + 延伸细横线**，比纯下划线更有层级感。

### 双栏（sidebar / creative）
左栏 58—64mm 放技能、联系方式、证书、兴趣；右栏放经历、教育、项目。

⚠️ **必须同时提供单栏版**。部分 ATS 解析器会横向读满一行再切下一行，导致左右栏内容被拼成一句乱语。Greenhouse 等系统明确把 columns 列为解析失败原因。

**侧栏高度**：侧栏内容少时会出现大片留白。这是正常的 —— 留白优于填充。与其塞内容，不如把技能写得更有层次。

## 五、分区顺序

**分两种情形**，取决于有没有实习/项目经历：

**有实习或项目经历（应届生投实习/校招常见）** —— 实践优先，学历放后面：

1. 个人简介（可选，但强烈建议有）
2. 实习经历 / 工作经历
3. 项目经历
4. 教育经历
5. 专业技能
6. 荣誉奖项 / 证书

**无实习的在校生** —— 学历优先：

1. 个人简介
2. 教育经历
3. 实习经历 / 项目经历
4. 专业技能
5. 荣誉奖项 / 证书

`lint_resume.py` 会按数据实际情况给出对应建议。

### 分区名必须用标准词
✅ 教育经历、实习经历、工作经历、项目经历、专业技能、荣誉奖项、证书、语言能力
❌ 我的成长之路、亮点集结地、我的技能武器库

创意分区名会让解析器无法归类，ATS 只会读到一串无法理解的标题。

## 六、项目符号（bullet）

- 每段经历 3—6 条，超过 6 条读者会放弃
- 每条不超过 2 行，单条 60 字以内
- 以**动作动词开头**，把"负责"整词删掉
- 量化：比例、金额、人数、周期、次数、规模
- 用普通圆点符号（disc），不用装饰性图标 —— 图标字体在 ATS 解析中经常整段丢失

### 句式模板
```
动作动词 + 具体做法 + 量化结果
```
- ❌ 负责店铺日常运营
- ✅ 接管天猫店铺日常运营，通过重排选品结构与详情页 A/B 测试，将单品转化率由 1.8% 提升至 2.6%

## 七、技能呈现

**用标签分类，不要用进度条/星级/雷达图。**

### 排版结构：分组标签独占一行，胶囊整行铺开

```
数据与工具
[Excel（数据透视表、函数建模）] [飞书多维表格] [问卷设计与调研数据分析] [PowerPoint 汇报材料制作]

电商运营
[选品与定价分析] [店铺后台管理与商品上架] [竞品对标分析] [活动策划与促销执行] [抖音短视频内容策划]
```

**不要用「左标签 + 右胶囊」两栏网格。**
试过，胶囊列被标签挤窄，条目一多就产生孤儿行（末行只剩一个胶囊），整块看起来凌乱。
标签独占一行时，胶囊能占满 178mm 整宽，换行次数更少、排列更整齐。

理由：`Python: 4/5` 无法解释"4"是什么，读者只能猜。技能条目应该占据空间，而不是用图形占位。技能条目尽量用一行罗列，不要一个技能一行（浪费 10 行版面）。

## 八、ATS 硬性规则

以下几条破坏了就别投：

| 规则 | 原因 |
|---|---|
| 单栏（首选） | 双栏会跨栏错读 |
| 标准分区名 | 解析器靠标题归类 |
| 真实可选中文字 | 图片文字、文本框、页眉页脚会被跳过 |
| 不用表格排版正文 | 表格解析极易错乱 |
| 联系方式在正文顶部 | 放页眉页脚会被跳过 |
| 真实字体，不小于 10pt | 生僻字体回退成方块 |
| 文本型 PDF | 扫描件/图片型 PDF 完全不可解析 |
| 不用装饰性图标字符 | ★◆■ 等字符常被整段丢弃 |

**自检方法**：导出 PDF 后，把内容复制粘贴到纯文本编辑器，看姓名、联系方式、经历顺序是否还正常。顺序乱了 → 双栏版不能用于线上投递。

### 照片占位框

无照片时渲染一个标准尺寸的虚线占位框，提示用户该放什么规格的图。

**它是「指引」，不是「内容」** —— 用轻量虚线描边 + 小字提示，
不做填充底、不用大图标。画得太重会在页眉右侧留出一个扎眼的 25×35mm 空洞，
视觉上比不放照片还糟。

## 十一、排查清单

简历看起来不对劲时，按顺序排查：

1. **字体回退了吗？** → 检查 PDF 里是否出现方块或错位字形
2. **行距被压了吗？** → 正文行距应 ≥1.4，字母不应相叠
3. **分区间距一致吗？** → 所有分区间距应完全相同
4. **对齐统一吗？** → 日期右对齐要全篇一致
5. **换行断得好看吗？** → 标题与组织名之间不应断行
6. **留白够吗？** → 页面下半部分空白超过 1/3 时应补内容或压缩
7. **一页装得下吗？** → 装不下时删旧内容，而不是缩字号或压边距
